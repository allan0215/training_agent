# Training Agent V1 Specification

## 1. V1의 목적

Training Agent V1은 사용자의 예정 훈련과 실제 수행 기록을 관리하고, 사용자의 운동 선호도, 수행 가능 여부, 일시적 제한, 훈련 장소와 장비를 반영하여 이번 주 훈련의 부족한 부분을 분석하고 보완 운동을 추천하는 시스템이다.

V1의 핵심 흐름은 다음과 같다.

1. 예정된 훈련을 등록한다.
2. 실제로 수행한 훈련을 기록한다.
3. 운동 장소, 장비, 선호도, 수행 가능 여부와 제한을 관리한다.
4. 이번 주 예정 훈련과 실제 수행량을 분석한다.
5. 부족하거나 과도한 움직임 패턴을 찾는다.
6. 현재 수행할 수 있는 보완 운동을 추천한다.
7. 추천 이유를 설명한다.
8. 사용자가 승인한 추천을 예정 훈련으로 저장한다.
9. 기존 기록을 조회, 수정, 삭제하거나 마지막 변경을 되돌릴 수 있다.

---

## 2. V1에서 구현하지 않는 기능

다음 기능은 V1 이후에 구현한다.

* 사진이나 스크린샷에서 훈련 내용을 자동 추출하는 기능
* 손글씨 칠판 사진 인식
* 근육통과 수행 변화에 따른 개인 근육 부하 자동 보정
* 자동 회복도 계산
* 상세한 근육별 피로 예측
* 훈련 영상을 이용한 자세 분석
* Strava, Garmin, Apple Health 연동
* Google Calendar와 Notion 연동
* 자동 주간 보고서와 능동적 알림
* 장기 훈련 프로그램 자동 생성

V1의 데이터 구조는 위 기능을 나중에 추가할 수 있도록 설계하되, 해당 기능을 V1에서 실제로 동작시키지는 않는다.

## 3. 핵심 용어

### Session

시간과 장소가 이어지는 한 번의 훈련 단위다.

예:

* 오전 야외 러닝
* 저녁 크로스핏 박스 훈련

같은 날짜라도 시간과 장소가 명확히 나뉘면 서로 다른 세션으로 기록한다.

### Block

한 세션 안에서 목적, 수행 방식, 결과 측정 방식 또는 프로그램 출처를 공유하는 운동 묶음이다.

예:

* HWPO 백스쿼트 스트렝스
* Mayhem 메트콘
* 개인 등 근비대 보조운동
* Zone 2 바이크

운동 하나마다 별도 블록을 만드는 것은 아니다. 같은 목적과 흐름을 공유하는 여러 운동은 하나의 블록에 포함될 수 있다.

### Program

HWPO, Mayhem 등 훈련 블록의 출처가 되는 프로그램이다.

프로그램은 세션이나 블록의 필수 부모가 아니다.

* 프로그램과 관계없는 세션을 만들 수 있다.
* 프로그램과 관계없는 블록을 만들 수 있다.
* 한 세션 안에 여러 프로그램에서 가져온 블록이 들어갈 수 있다.
* 하나의 블록이 여러 프로그램을 참고할 수도 있다.

### Program Run

사용자가 특정 프로그램을 실제로 진행하는 기간이다.

같은 프로그램을 중단했다가 다시 시작하면 별도의 Program Run으로 기록한다.

### Planned

앞으로 수행할 예정이거나 기존에 처방된 훈련 내용이다.

### Actual Workout

사용자가 실제로 수행한 훈련 내용이다.

계획과 실제 수행은 절대 같은 기록을 덮어쓰지 않는다. 실제 수행 기록은 예정 블록과 선택적으로 연결한다.

## 4. 세션과 블록의 분류

### 블록의 수행 형태

`block_type`은 운동의 수행 형태를 나타낸다.

* resistance
* metcon
* cardio
* skill
* mobility
* recovery
* warmup
* cooldown
* other

### 블록의 훈련 목적

`training_goal`은 운동의 목적을 나타낸다.

* maximal_strength
* strength
* hypertrophy
* power
* weightlifting_technique
* gymnastics_skill
* conditioning
* aerobic_endurance
* speed
* mobility
* recovery
* mixed
* unknown

수행 형태와 목적은 분리한다.

예:

* 바벨 로우: `resistance + hypertrophy`
* 백스쿼트 3RM: `resistance + maximal_strength`
* 가벼운 스쿼트 기술 연습: `resistance + weightlifting_technique`

---

## 5. 계획 상태

예정된 세션과 블록은 다음 상태 중 하나를 가진다.

* planned
* completed
* partially_completed
* skipped
* rescheduled
* cancelled

주간 실제 수행량에는 실제 수행 기록만 포함한다.

계획된 세트 수를 수행한 세트 수로 간주해서는 안 된다.

---

## 6. 운동 종목 표준화

모든 운동은 표준 운동 사전에 연결한다.

예:

* 백스쿼트
* 백 스쿼트
* Back Squat
* BS

위 표현은 모두 같은 표준 운동인 `Back Squat`으로 연결한다.

새로운 운동명이 기존 운동과 정확히 연결되지 않으면 자동으로 별도 운동을 생성하지 않는다. 기존 운동 후보를 제시하거나 사용자에게 확인받는다.

---

## 7. 움직임 패턴

V1은 다음 움직임 패턴을 기본 분석 단위로 사용한다.

* squat
* hinge
* horizontal_push
* horizontal_pull
* vertical_push
* vertical_pull
* knee_flexion
* carry
* locomotion
* jump
* core
* other

한 운동은 여러 움직임 패턴과 연결될 수 있다.

예:

* Thruster: squat + vertical_push
* Clean: hinge + squat
* Burpee: horizontal_push + locomotion
* Pull-up: vertical_pull

움직임 패턴의 상대적 기여도는 일반적인 기본값을 사용한다. V1에서는 사용자 개인의 근육 사용 패턴을 자동 학습하지 않는다.

---

## 8. 주간 분석 기간

사용자의 기준 시간대는 `Asia/Seoul`이다.

한 주는 다음 범위로 계산한다.

* 시작: 월요일 00:00
* 종료: 일요일 23:59:59

주간 분석 결과는 다음 두 값을 구분해서 보여준다.

### 현재까지 실제 수행량

이번 주에 이미 실제로 수행한 훈련량이다.

### 예정 포함 예상량

현재까지의 실제 수행량과 남은 기간에 예정된 훈련량을 합한 예상치다.

예:

* 수평 당기기 실제 수행: 4세트
* 남은 예정: 3세트
* 주간 예상: 7세트
* 주간 목표: 10세트
* 예상 부족: 3세트

---

## 9. 훈련량 계산 원칙

### 저항운동

저항운동은 움직임 패턴별 유효 세트를 주된 기준으로 사용한다.

V1의 유효 세트 기본 규칙:

* 워밍업 세트는 제외한다.
* 실제로 수행한 작업 세트만 계산한다.
* 계획 분석에서는 예정 작업 세트를 별도로 계산한다.
* 세트 정보가 불완전하면 낮은 신뢰도로 표시한다.
* RPE나 RIR가 있다면 함께 보관하지만 V1의 기본 세트 수를 자동 변경하지 않는다.

### 메트콘

메트콘은 저항운동 유효 세트와 동일하게 계산하지 않는다.

메트콘은 다음 정보를 별도로 기록한다.

* 포함된 주요 움직임 패턴
* 운동별 반복 수
* 사용 중량
* Rx 또는 스케일 여부
* 수행 시간
* 라운드 또는 총 반복 수

분석 시에는 `metcon exposure`로 표시한다.

예:

* 수직 당기기 저항운동: 3세트
* 수직 당기기 메트콘 노출: 높음

### 카디오

카디오는 다음 기준으로 기록한다.

* 시간
* 거리
* 페이스 또는 속도
* 심박수
* 강도 구간
* 인터벌 구조

카디오 시간을 저항운동 유효 세트로 변환하지 않는다.

---

## 10. 훈련 목표

“부족하다”는 판단은 사용자가 설정한 목표와 비교해서 이루어진다.

최소한 다음 목표 유형을 지원한다.

* 움직임 패턴별 주간 유효 세트
* 특정 운동의 주간 빈도
* 카디오 주간 시간
* 카디오 주간 거리
* 특정 기술의 주간 연습 횟수

목표값이 없는 항목은 부족하다고 확정하지 않는다.

목표값이 없을 때는 다음과 같이 상대적인 관찰만 제공한다.

* 다른 패턴보다 적게 포함되어 있다.
* 최근 몇 주 동안 노출이 감소했다.
* 이번 주 계획에 해당 패턴이 없다.

---

## 11. 장소와 장비

훈련 장소와 해당 장소에서 사용할 수 있는 장비를 분리해서 저장한다.

장소 예:

* home_gym
* commercial_gym
* crossfit_box
* outdoor
* temporary_location

장비 예:

* barbell
* squat_rack
* dumbbell
* kettlebell
* pullup_bar
* cable_machine
* rings
* climbing_rope
* rower
* ski_erg
* assault_bike

운동 추천은 장소의 이름이 아니라 해당 장소에서 실제로 사용할 수 있는 장비를 기준으로 필터링한다.

---

## 12. 운동 선호도

운동 선호도는 다음 5단계로 기록한다.

* 2: 매우 선호
* 1: 선호
* 0: 중립
* -1: 비선호
* -2: 적극 회피

선호도는 추천 순위를 조정하는 소프트 조건이다.

운동 목표 달성에 필요한 운동을 사용자가 싫어한다는 이유만으로 반드시 제외하지는 않는다. 가능한 대체 운동이 있다면 선호도를 반영해 대안을 우선 제시한다.

---

## 13. 운동 수행 가능 여부

운동 수행 능력은 다음 상태를 사용한다.

* available
* learning
* scaled_only
* restricted
* unavailable
* unknown

예:

* Ring Muscle-up: unavailable
* Rope Climb: scaled_only
* Back Squat: available
* Handstand Walk: learning

기술적으로 수행할 수 없는 것과 현재 통증 때문에 제한된 것은 서로 다른 데이터로 저장한다.

---

## 14. 일시적 제한과 통증

일시적 제한에는 다음 정보를 저장한다.

* 제한 대상 운동 또는 움직임 패턴
* 제한 사유
* 시작일
* 예상 종료일
* 제한 수준
* 사용자 메모
* 현재 상태

예상 종료일이 지나도 자동으로 제한을 해제하지 않는다. 확인이 필요한 상태로 변경한다.

근육통과 통증은 같은 개념으로 취급하지 않는다.

* soreness: 일반적인 운동 후 근육통
* pain: 관절, 힘줄, 신경 또는 부상 가능성이 있는 불편

V1에서는 통증을 의료 진단하지 않는다.

---

## 15. 추천 엔진의 처리 순서

추천 후보는 반드시 다음 순서로 평가한다.

1. 현재 부상과 일시적 제한 검사
2. 운동 수행 가능 여부 검사
3. 현재 장소의 장비 검사
4. 이번 주 실제 수행량 검사
5. 이번 주 남은 예정 훈련 검사
6. 주간 목표 대비 부족량 검사
7. 다음 훈련과의 충돌 검사
8. 운동 선호도 반영
9. 시간과 수행 가능량 반영
10. 최종 추천 생성

제한, 수행 가능 여부, 장비는 하드 조건이다.

선호도와 운동 다양성은 소프트 조건이다.

---

## 16. 추천 결과

추천에는 반드시 다음 정보가 포함된다.

* 추천 운동
* 세트와 반복 또는 시간
* 수행 장소
* 충족하려는 움직임 패턴 또는 목표
* 추천 이유
* 제외한 주요 대안과 제외 이유
* 추천의 신뢰도
* 계획에 추가할지 여부

예:

체스트 서포티드 로우 3세트를 추천합니다.

이유:

* 이번 주 수평 당기기 예상량이 목표보다 3세트 부족합니다.
* 수직 당기기는 풀업 메트콘으로 이미 충분합니다.
* 현재 헬스장에 필요한 장비가 있습니다.
* 내일 예정된 밀기 중심 WOD와 직접 충돌하지 않습니다.

---

## 17. 추천 승인

추천은 사용자의 승인 전에는 실제 훈련이나 예정 훈련으로 취급하지 않는다.

사용자가 승인하면 추천 내용을 새로운 예정 블록으로 저장한다.

추천을 계획에 추가한 뒤에는 주간 분석을 다시 계산한다.

같은 부족량을 이미 승인된 추천으로 충족할 예정이라면 동일한 추천을 반복하지 않는다.

---

## 18. 기록 저장 정책

### 바로 저장할 수 있는 작업

다음 조건을 모두 충족하는 명확하고 비파괴적인 기록:

* 날짜가 명확함
* 운동명이 표준 운동과 연결됨
* 세트, 반복 또는 결과가 충분히 명확함
* 기존 기록을 수정하거나 삭제하지 않음

### 확인이 필요한 작업

* 날짜가 모호함
* 운동명이 여러 종목으로 해석될 수 있음
* 중량 단위가 모호함
* 세트나 반복이 불완전함
* 기존 기록과 중복 가능성이 있음
* 수정 또는 삭제 요청
* 여러 기록을 한 번에 변경하는 요청

AI가 구조화한 내용을 바로 SQL에 저장하지 않는다. Python 검증과 서비스 계층을 통과한 데이터만 저장한다.

---

## 19. 수정, 삭제, 되돌리기

V1은 다음 요청을 지원한다.

* 방금 기록 취소
* 특정 세트의 중량 수정
* 세트 수 수정
* 특정 블록 삭제
* 특정 세션 삭제
* 예정일 변경
* 마지막 변경 되돌리기

수정과 삭제 전에는 변경 대상을 요약하고 확인받는다.

중요한 기록은 즉시 물리적으로 삭제하지 않고 `deleted_at`을 사용하는 소프트 삭제를 우선 적용한다.

모든 변경은 감사 기록에 남긴다.

감사 기록에는 다음이 포함된다.

* 작업 종류
* 변경 대상
* 변경 전 데이터
* 변경 후 데이터

## 20. 미래 개인화 확장성

V1은 개인화 부하 계산을 수행하지 않는다.

다만 추후 다음 데이터를 수집할 수 있도록 확장 가능해야 한다.

* 운동 중 먼저 지친 부위
* 운동 직후 체감 피로
* 다음날 근육통
* 통증
* 세트 간 수행 저하
* 장기 수행능력 변화
* 수면, 컨디션, 스트레스

원본 훈련 기록과 사용자 관측 데이터는 영구적인 사실로 보관한다.

개인별 부하 보정값과 회복 모델은 원본 데이터와 분리된 파생 데이터로 관리하며, 나중에 알고리즘이 바뀌면 다시 계산할 수 있어야 한다.

## 21. V1 완료 조건

다음 시나리오가 모두 동작하면 V1이 완료된 것으로 본다.

### 계획 등록

사용자가 이번 주 HWPO 스트렝스와 Mayhem 메트콘을 예정 훈련으로 등록할 수 있다.

### 실제 기록

사용자가 실제 세트, 중량, 반복, RPE와 메트콘 결과를 기록할 수 있다.

### 복합 세션

한 세션 안에 서로 다른 프로그램 출처의 여러 블록을 기록할 수 있다.

### 사용자 조건

운동 장소, 장비, 운동 선호도, 수행 가능 여부와 일시적 제한을 관리할 수 있다.

### 주간 분석

이번 주 실제 수행량과 남은 예정량을 함께 분석할 수 있다.

### 추천

주간 목표에서 부족한 패턴을 찾아 현재 수행할 수 있는 보완 운동을 추천할 수 있다.

### 추천 설명

추천 이유와 제외 조건을 사용자에게 설명할 수 있다.

### 추천 승인

사용자가 추천을 승인하면 예정 블록으로 저장된다.

### 기록 관리

과거 기록을 조회, 수정, 삭제하고 마지막 변경을 되돌릴 수 있다.

## 22. 설계 원칙

* SQLite가 훈련 사실의 최종 기준이다.
* AI의 대화 기억을 훈련 기록으로 사용하지 않는다.
* AI는 SQL을 직접 작성하거나 실행하지 않는다.
* 모든 쓰기 작업은 검증된 Python 서비스 함수를 통해 실행한다.
* 계획과 실제 기록은 분리한다.
* 세션과 블록은 프로그램에 종속되지 않는다.
* 복잡한 메트콘을 저항운동 유효 세트와 동일시하지 않는다.
* 추천은 제한과 장비를 먼저 검사한다.
* 추천 결과는 근거와 신뢰도를 함께 표시한다.
* 원본 기록과 파생 분석 결과를 분리한다.
* 삭제와 수정은 추적 가능해야 한다.
